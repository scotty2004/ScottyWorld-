# ScottyWorld Phase 11 — Launch & Final Polish

Phase 11 prepares the Phase 1–10 platform for a controlled production launch.

## Added

- Production SEO metadata with canonical URL and social metadata.
- `robots.txt` and `sitemap.xml` generated by Next.js.
- `security.txt` contact/policy convention.
- `/api/ready` database readiness endpoint.
- Structured JSON server logger foundation.
- Launch checklist covering secrets, database, domain, storage, AI, bot runtime, payments, email, backups, monitoring and security.
- Final end-to-end smoke-test plan.
- Backup/restore runbook.
- Performance and accessibility checklist.

## Required production environment

Set at minimum:

- `NEXT_PUBLIC_SITE_URL`
- `DATABASE_URL`
- Your production authentication/session secret variables.
- Provider credentials required by integrations you actually enable.

Never commit `.env` files, production credentials, private keys, webhook secrets, database URLs or bot session credentials.

## Deployment sequence

1. Provision PostgreSQL.
2. Configure production environment variables.
3. Run `npm ci`.
4. Run `npm run db:generate`.
5. Run `npm run db:migrate`.
6. Run `npm run build`.
7. Start with `npm run start`.
8. Put the app behind HTTPS.
9. Point the domain to the reverse proxy/CDN.
10. Verify `/api/health` and `/api/ready`.
11. Test authentication, RBAC, AI, bot runtime, cloud upload, payments and email after providers are configured.
12. Confirm backups and restore procedures before public launch.

## Database backup runbook

Use your PostgreSQL provider's native automated backups where available. Keep retention appropriate to your service needs and periodically test restoring a backup into a separate staging database.

A restore test should never overwrite the live database.

## Observability

Monitor at least:

- HTTP 5xx rate
- response latency
- database connection/errors
- authentication failures
- webhook failures
- bot runtime failures
- storage upload failures
- CPU/RAM/disk
- backup success

The built-in logger is a small foundation. For multiple instances, send structured logs to a centralized logging provider.

## Final smoke test

### Public
- Homepage loads on mobile and desktop.
- Navigation works.
- Dark/light mode works.
- PWA manifest/service worker load.
- SEO metadata is present.
- `/robots.txt` and `/sitemap.xml` respond.

### Authentication
- Register.
- Login.
- Logout.
- Protected routes redirect unauthenticated users.
- Session expiry/revocation behaves correctly.
- Password reset and verification flows are configured before launch.

### Core platform
- Dashboard.
- Scotty AI.
- Bot Studio.
- Developer Hub.
- Academy.
- Community.
- Marketplace.
- Coins/referrals.
- Cloud.
- Security Center.
- Pro/subscriptions.

### Admin
- Non-admin users cannot access `/admin`.
- Role checks happen server-side.
- Sensitive admin actions are audited.
- Secrets are never returned to clients.

### Integrations
- AI provider configured and rate-limited.
- Bot runtime reachable and authenticated.
- Storage adapter issues scoped upload URLs.
- Payment webhook rejects invalid signatures and handles duplicate events.
- Email adapter sends through a configured provider.

## Accessibility

Check keyboard navigation, visible focus, form labels, contrast, reduced motion, touch target size and meaningful page titles. Do not rely on color alone.

## Performance

Before launch, test on a real mid-range Android phone and a slower network. Check bundle size, image dimensions, lazy loading, cache behavior and API latency.

## Important

Phase 11 does not invent vendor credentials or pretend integrations are live. Real providers still need to be configured and tested in staging.
